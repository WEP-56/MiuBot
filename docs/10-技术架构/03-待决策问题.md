# 待决策问题与设计记录

本文件用作 ADR 前的讨论池，避免猜测尚未拍板的实现细节。

## 当前已确认的方向

| 事项 | 决策 |
|---|---|
| 产品名 | Miubot（角色昵称 Miu） |
| 前端布局 | 左侧侧栏；高级配置折叠；日志/设置底部固定 |
| Agent 基底 | 更倾向 Fork Pi，而不是单纯依赖 SDK |
| 核心复用 | Agent Core、Provider Core、Plugin Core |
| 核心改造 | Tool 定义/权限、社交上下文管理、Plugin Core 增量能力 |
| 初始产品焦点 | QQ 群聊/私聊、提供商、人设、调试与易用性 |

## 已确定并已落地的工程选择

| 事项 | 当前结论 |
|---|---|
| Pi 基线 | Pi 1.3.0，冻结于 tag `baseline-pi-1.3.0` |
| 前端 | React + Vite |
| QQ 接入 | 仅 QQ 官方 Bot；支持扫码和 AppID/AppSecret 凭据方式 |
| 当前部署形态 | Node.js 单进程，HTTP API 与 QQ 适配器由 `apps/server` 装配 |
| 包管理 | npm workspaces，包位于 `packages/*` 与 `apps/*` |
| 主动行为默认值 | 全局关闭；群级智能插话单独启用后才参与处理 |
| 智能插话聚合 | 固定时间窗口聚合；支持纯概率与模型判断模式 |

## 尚未决定（建议按优先级评审）

以下只保留尚未拍板、且仍影响架构走向的问题：

| 问题 | 候选/衡量项 | 影响 |
|---|---|---|
| Plugin Core 实现 | 同进程可信插件起步 / 独立进程隔离 | 安全边界与开发复杂度 |
| 持久化方案 | SQLite + 轻量查询层 / ORM；迁移与备份策略 | 数据可靠性、迁移成本与运维复杂度 |
| 配置继承范围 | 全局、Bot、群/个人、会话之间的覆盖关系 | 当前基础对象配置与后续会话级配置的职责边界 |
| 任务模型路由 | 明确任务槽位与回退链的首期范围 | 成本、能力匹配和故障恢复 |
| 插件包来源与信任 | 可信目录、签名/审核、权限声明与撤销 | 插件执行权限和安装风险 |
| 记忆保存 | 手工优先 / AI 建议需审核 / 自动提取 | 隐私与功能复杂度 |
| UI 扩展方式 | JSON Schema 配置面板 / Web 插件沙箱 | 插件体验、安全 |

## 推荐讨论顺序

1. **补齐基础数据可靠性**：选择正式持久化方案并定义迁移、备份和恢复。
2. **定插件信任与运行边界**：决定插件来源、权限审核和隔离策略，再接入安装能力。
3. **细化模型路由**：确定任务槽位、回退行为和用量记录的首期范围。
4. **明确配置继承**：界定群/个人配置与多个会话配置的优先关系和生效提示。
5. **再扩展高级能力**：MCP、表情包、记忆、定时任务与主动发起按路线图推进。

## 文档变更原则

每次决定一项重要取舍时，记录 `问题 / 备选方案 / 结论 / 理由 / 影响模块 / 日期`。保持页面文档描述产品体验，架构文档描述实现约束，不把暂定实现伪装为已完成能力。
