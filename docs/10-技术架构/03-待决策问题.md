# 待决策问题与设计记录

本文件用作 ADR 前的讨论池，避免猜测尚未拍板的实现细节。

## 当前已确认的方向

| 事项 | 决策 |
|---|---|
| 产品名 | Miubot（角色昵称 Miu） |
| 前端布局 | 左侧侧栏；高级配置折叠；日志/设置底部固定 |
| Agent 基底 | 更倾向 Fork Pi，而不是单纯依赖 SDK |
| 核心复用 | Agent Core、Provider Core、Plugin Core |
| 核心改造 | Tool 定义/权限、社交上下文管理、Plugin Core 增量能力 |
| 初始产品焦点 | QQ 群聊/私聊、提供商、人设、调试与易用性 |

## 尚未决定（建议按优先级评审）

| 问题 | 候选/衡量项 | 影响 |
|---|---|---|
| 首个 QQ 接入 | QQ 官方 API / OneBot v11 (NapCat) | MVP 验证速度、能力差异、维护与合规 |
| 首个部署形态 | Node 单进程 / 多进程 | 插件隔离、打包与资源成本 |
| Pi Fork 基线 | 固定稳定 commit / 选定 tag | 上游同步、许可证、Extension 兼容 |
| Plugin Core 实现 | 同进程可信插件起步 / 独立进程隔离 | 安全边界与开发复杂度 |
| 前端框架 | React + Vite（暂拟） / 其他 | UI 生态、开发效率 |
| ORM/存储 | SQLite + ORM 或轻量查询层 | 数据迁移、备份与性能 |
| Context 消息聚合 | 固定时间窗口 / 话题与引用组合 | 智能插话自然度与开销 |
| 模型路由缺省策略 | 明确模型槽位 + 可选 Auto | 透明度、易配置性 |
| 主动行为缺省 | 全局与群默认关闭（建议） | 打扰风险、成本、用户信任 |
| 记忆保存 | 手工优先 / AI 建议需审核 / 自动提取 | 隐私与功能复杂度 |
| UI 扩展方式 | JSON Schema 配置面板 / Web 插件沙箱 | 插件体验、安全 |

## 推荐讨论顺序

1. **先定消息与会话基础契约**：NormalizedEvent、Conversation、Trace。
2. **再定平台接入 MVP**：首个 QQ 协议、连接向导字段、发送验证能力。
3. **再验证 Fork 边界**：哪些 Pi 模块沿用、哪些要剥离/修改。
4. **接着做可观察的完整消息闭环**，确认 UI 与日志定位体验。
5. **最后延伸高级配置**：主动行为、表情包、插件、记忆与任务。

## 文档变更原则

每次决定一项重要取舍时，记录 `问题 / 备选方案 / 结论 / 理由 / 影响模块 / 日期`。保持页面文档描述产品体验，架构文档描述实现约束，不把暂定实现伪装为已完成能力。
