## 改写要点

- **导入重写**：跨包相对导入改为 `@miubot/<pkg>/<path>`，由根 `tsconfig.json` 的 `paths` 直连源码，不产出 dist。
- **终端类型兼容层**：`packages/shared/src/terminal.ts` 声明扩展 API 里用到的 TUI/Theme/Keybindings 类型，值层面是空实现。它只为让扩展 API 通过类型检查而存在，不是给新代码用的。
- **主题资源**：`loadThemeFromPath` 恒返回 `undefined`，主题资源列表始终为空。
- **模型数据**：`providers/data/*.json` 原本被上游 `.gitignore` 排除，迁移后需运行 `node packages/provider/scripts/generate-models.ts --data-only` 重新生成（43 个 provider 目录文件）。这些文件现在是构建产物，未纳入版本库。
- **类型声明**：`proper-lockfile`、`semver`、`hosted-git-info` 没有上游类型包，在 `packages/shared/src/types/` 下补了最小声明。

## 当前未完成项

1. `session` 与 `plugin` 存在类型层面的双向引用（扩展 API 需要会话类型）。运行时依赖目前是单向的，后续要么抽出契约包，要么接受这个环。
2. `session/src/package-manager.ts`（约 87 KB）仍保留但未接线。Miubot 插件安装与信任模型尚未定，需要确定方案后再决定是否复用。
3. `session/src/{bug-report,bug-report-upload,crash-log,footer-data-provider}` 等 CLI/TUI 设施仍保留，等待插件体系和服务端诊断能力稳定后再评估清理。
4. Pi 上游 MCP / code-mode 扩展没有移植。MCP 客户端包仍在，但服务配置、授权与工具接线尚未实现；代码执行扩展也未接入。
5. `session` / `plugin` 的类型环尚未通过独立契约包解决；`packages/platform` 等领域边界也还没有拆成独立包，当前官方 QQ 适配器由 `apps/server` 装配。
6. Pi 的 Shell 与文件工具已通过 Pi Agent Loop 接入，并可在高级配置中管理；网页搜索 `web_search` 已提供，工具全局设置与群/个人级 `useTools` 开关共同控制可用工具。高风险工具默认关闭。
7. TTS、生图、表情包、记忆、定时任务、主动发起及插件生命周期等产品能力仍未完成，具体优先级见路线图。提供商页面中的 TTS 与图像生成入口目前仅提示待开发。

## 工程约束

根 `package.json` 已恢复 `npm workspaces`（`packages/*`、`apps/*`）；包依赖由各 workspace 声明。根 `tsconfig.json` 仍用 paths 直连源码以支持开发期类型检查，Vitest 使用 workspace 包解析。当前工作区位于 NTFS，原先因 exFAT 导致的 workspace 阻塞已解除。
