## 改写要点

- **导入重写**：跨包相对导入改为 `@miubot/<pkg>/<path>`，由根 `tsconfig.json` 的 `paths` 直连源码，不产出 dist。
- **终端类型兼容层**：`packages/shared/src/terminal.ts` 声明扩展 API 里用到的 TUI/Theme/Keybindings 类型，值层面是空实现。它只为让扩展 API 通过类型检查而存在，不是给新代码用的。
- **主题资源**：`loadThemeFromPath` 恒返回 `undefined`，主题资源列表始终为空。
- **模型数据**：`providers/data/*.json` 原本被上游 `.gitignore` 排除，迁移后需运行 `node packages/provider/scripts/generate-models.ts --data-only` 重新生成（43 个 provider 目录文件）。这些文件现在是构建产物，未纳入版本库。
- **类型声明**：`proper-lockfile`、`semver`、`hosted-git-info` 没有上游类型包，在 `packages/shared/src/types/` 下补了最小声明。

## 已知缺口

1. `session` 与 `plugin` 存在类型层面的双向引用（扩展 API 需要会话类型）。运行时依赖目前是单向的，后续要么抽出契约包，要么接受这个环。
2. 包管理设施（`session/src/package-manager.ts`，约 87 KB）用于从 npm/git 安装 Pi 扩展。Miubot 插件形态未定，暂时保留未接线。
3. `session/src/{bug-report,crash-log,footer-data-provider,keybindings}` 等文件是 CLI 残留，保留但未使用，判断后清理。
4. `packages/plugin` 暂不支持 MCP 与代码执行扩展，需要按 QQ 场景重新设计。
5. `apps/{server,web}` 只有职责说明，没有实现。
6. 工具集仍是 Pi 的编程工具（bash/read/write/edit/grep/find/ls）。按设计文档，这些不应作为 QQ 群聊的默认工具。

## 工程约束

E: 盘是 exFAT，不支持符号链接，因此不能使用 npm workspaces。仓库改为单包：根 `package.json` 声明全部依赖，`@miubot/*` 由 `tsconfig.json` 的 `paths` 与 `vitest.config.ts` 的 alias 解析。若迁到 NTFS，可恢复 workspaces。
