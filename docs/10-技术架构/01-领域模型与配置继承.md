# 领域模型与配置继承

## 核心实体（概念）

| 实体 | 核心字段 | 关系 |
|---|---|---|
| BotInstance | id, platform, adapter, identity, status, configRef | 1:N Conversation |
| Provider | id, protocol, endpoint, credentialRef, status | 1:N Model |
| Model | id, providerId, modelKey, capabilities, pricing | 被 Route 与会话引用 |
| TaskRoute | slot, primaryModelId, fallbackModelIds, policy | 可由全局/Bot/会话定义 |
| Persona | id, version, prompt, preferences | 可绑定多个会话 |
| Conversation | id, botInstanceId, type, externalId, configOverrides | 1:N Message |
| Message | id, conversationId, actorId, segments, replyTo, time | 关联 Trace |
| AgentRun | id, traceId, conversationId, inputSnapshot, status | 1:N ModelCall/ToolCall |
| Memory | id, scope, subject, content, source, expiresAt | 检索时权限过滤 |
| Plugin | id, version, status, manifest, permissions | 提供各种 Capability |
| Grant | subjectScope, capabilityId, effect, constraints | 限制 Tool 使用 |
| ScheduledTask | id, schedule, actor, target, permissions, status | 1:N TaskRun |

## 配置继承规则

推荐结构：

```text
全局默认（Global）
  ↓
Bot 实例覆盖（Bot）
  ↓
会话覆盖（Conversation）
  ↓
成员限定覆盖（Participant：只有适用字段）
```

### 有效配置求值

1. 各字段先有系统安全边界和全局默认值。
2. 按层级找出最后一个**显式覆盖**值，而不是比较是否与默认值相等。
3. 对配置进行合法性检查：引用是否存在，平台能力是否支持，权限是否允许。
4. 权限类配置按**限制性合并**执行：下层不能解除由安全策略设定的绝对禁止。
5. 返回 `(effectiveValue, sourceScope, sourceEntityId, lockedReason?)`，供 UI 显示生效来源与禁用原因。

### 示例

```json
{
  "field": "personaId",
  "effectiveValue": "persona_miu",
  "sourceScope": "conversation",
  "sourceEntityId": "conv_123",
  "lockedReason": null
}
```

UI 显示“当前会话覆盖 · 恢复继承”。如果人格实体被删除，必须显示无效引用，不得静默改成其他人格。

## 配置字段类型

- `inherit`：当前层没有覆盖，采用上级。
- `override(value)`：当前层明确赋值，包括 `false`、`0`、空数组等合法值。
- `blocked(reason)`：上级安全边界强制禁止，当前层不可提升权限。

避免使用 `undefined/null/false` 混淆“未设置”“继承”“明确关闭”。

## 版本与一致性

- 配置更新记录操作主体、时间、旧值与新值；含密钥的字段只记录改变而非明文。
- AgentRun 保存当次配置快照引用/版本，避免后台修改后无法解释历史执行结果。
- 修改人格或任务路由不逆向改变历史聊天记录。

## 多 Bot 与跨会话隔离

会话/消息以内部标识与适配器外部标识映射；一个外部群 ID 在不同平台/不同 Bot 下不能无条件视为同一会话。群内用户身份与私聊主体应分别建模，跨域共享必须显式授权。

## 存储约定

初期可用 SQLite 做业务数据持久化，并对大型媒体文件存储引用；消息历史、运行 Trace 和日志各自有保留策略。高频日志和媒体不建议直接无限增长单个数据库。Schema 迁移需要版本管理和备份/恢复演练。
