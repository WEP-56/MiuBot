> 版本：v0.1 · 状态：需求与交互设计草案 · 更新：2026-10-20  
> 面向：Miubot 项目开发、界面设计、架构与后续 Agent 协作。  
> 本文档是设计提案，不表示对应功能已经实现。示例数据、界面文案与阈值均为建议值。

## 项目一句话定位

**Miubot 是一个基于 Fork Pi 内核、面向 QQ 社交聊天场景的可自托管 Agent 工作台。**

核心理念：**Mechanically strong, cognitively weak（机械能力强，认知干预弱）**。运行时、工具、权限、上下文组装、配置与可观察性由框架可靠提供；具体回复、何时使用工具等认知决策尽量交给模型，在授权边界内自主完成。

## 全局约定

- **平台**：QQ 官方、QQ OneBot 等目标社交平台或连接方式；**适配器**：承担协议实现的组件；**Bot 实例**：一个已配置或已连接的账号/应用。
- **提供商**：提供模型调用接口的服务或兼容端点；**模型**：具体能力实体；**任务路由**：将聊天、生图、语音等任务映射到模型和回退链。
- **人格**：身份、表达方式和偏好，不等于 Bot 实例，不直接拥有高危工具权限。
- **会话**：由平台、Bot、会话类型和对端标识界定的独立交流范围；群内成员有独立身份。
- **插件**：提供 Tool、事件处理、适配器、后台任务或 UI 等能力的可装卸扩展；**Tool** 只是插件可能提供的一种能力。
- **运行日志**：跨模块诊断记录；**消息记录**：会话里的业务历史；**调试 Trace**：一次处理过程的完整关联事件。

## 阅读顺序建议

先读「产品定位 → 导航 → 页面文档」，再读「Pi Fork → 领域模型 → 安全」。每页都给出核心交互、状态和验收要求。所有涉及外部平台具体支持能力的设计必须以接入适配器的真实能力为准，不承诺所有 QQ 接入方式都支持扫码、主动发消息等功能。
