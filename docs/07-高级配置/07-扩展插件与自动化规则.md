# 扩展插件与自动化规则

## 核心定位

Miubot 的 Plugin Core 不只是 Pi Tool 注册器：一个插件可注册工具、监听平台/Agent 事件、提供平台适配器、注册后台任务、扩展工作台设置界面。插件是能力和生命周期单元，Tool 是能力的一种。

## 页面

- `已安装`：插件列表、版本、来源、依赖、状态、权限、日志、卸载。
- `安装`：本地包/受信任源（MVP 先本地），显示 manifest 与风险提示。
- `自动化规则`：传统事件规则，适合“不需要 LLM”的处理。

## 建议 manifest 字段（概念）

```json
{
  "id": "miubot.plugin.example",
  "name": "Example Plugin",
  "version": "0.1.0",
  "apiVersion": "1",
  "capabilities": ["agent.tool", "event.handler", "ui.settings"],
  "permissions": ["network:example.com"],
  "entry": "dist/index.js"
}
```

## 生命周期与事件

- 生命周期：发现 → 校验 → 安装 → 配置 → 启用 → 停用 → 卸载。
- 扩展点：`platform.event`、`message.received`、`message.normalized`、`agent.beforeRun`、`tool.beforeExecute`、`agent.afterRun`、`message.beforeSend` 等。实际 Hook 以最终宿主协议定义。
- 每个 Hook 明确可读/可写字段、同步还是异步、优先级、超时、失败策略；避免插件隐式篡改消息。
- UI 扩展优先提供宿主渲染的 Schema/配置表单，复杂 UI 扩展需版本与安全边界。

## 权限模型

1. 安装时声明潜在能力和宿主权限。
2. 启用时由管理员批准运行范围。
3. Agent Tool 再经过 Bot/会话/用户有效权限过滤。
4. Tool 调用时宿主二次校验和审计；`Plugin 已启用` 不代表任何群友可调用。

**注意**：普通 Node 进程内插件没有操作系统级沙箱。若支持不可信第三方代码，应考虑独立进程/容器等真实隔离和 IPC，不能把 manifest 权限声明当成隔离保障。

## 自动化规则（非 Agent）

场景：入群欢迎、关键词回复、好友申请审批辅助、消息事件转发。提供 `事件 → 条件 → 动作` 可视化编辑，条件限制数量/优先级；执行仍走权限、速率限制与审计。与主动行为相区别：规则是明确条件触发、确定性动作，不必每次调用 LLM。

## 与 Pi Fork 的关系

尽可能适配 Pi 原有 Agent Tool/Extension 能力，但 Miubot 的 Plugin Core 负责额外宿主能力：事件总线、平台适配、后台生命周期、UI 扩展、安全授权。不承诺所有依赖终端 UI、工作目录和 Bash 的 Pi Extension 原样运行。

## 验收

- 一个示例插件可同时注册只读 Tool 和配置项；停用后均不可再调用。
- 插件崩溃有错误隔离与日志，不能导致所有 Bot 停机。
- 自动化规则与智能 Agent 的执行来源可在 Trace 中区分。
