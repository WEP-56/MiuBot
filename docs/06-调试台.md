# 调试台 · Agent 可观察与安全测试

**位置**：侧栏 / 调试台 · **目标**：不去真实 QQ 群反复试错，也能解释一次消息为什么回复、怎样回复、为什么没回复。

## 主要区域

```text
调试台                            [模拟聊天] [Trace 查询] [历史回放]
左侧：目标 Bot / 会话 / 人格 / 模型 / 能力
中间：测试对话/原始消息输入
右侧：执行时间线、最终上下文、Token、工具与发送状态
```

## 三种模式

**1. 模拟聊天**：选择或新建虚拟会话，测试当前配置或未保存人格草稿。默认不向任何真实 QQ 会话发送。外部工具同样默认受限，必要时使用 Mock 工具。

**2. Trace 查询**：按 Trace ID、Bot、群、时间、模型、错误类型过滤，查看一次处理的完整生命周期：`接收 → 标准化 → 触发/规则 → Context Build → 模型路由 → Agent Loop → Tool → 发送 → 结束`。

**3. 历史回放**：从会话中选一条真实历史事件，在测试环境重跑当前版本的处理流程。默认只读，不重放已产生副作用的 Tool，也不发真实消息。

## 一次 Trace 应展示什么

| 区域 | 内容 |
|---|---|
| 入站 | 原始事件摘要、标准化消息、来源、时间 |
| 决策 | 哪条规则放行/阻断、智能插话判断结果、冷却与权限 |
| 上下文 | 输入的历史片段、摘要来源、选入原因、Token 预算 |
| 路由 | 槽位、主模型、回退链、实际模型、原因 |
| Agent | 模型调用次数、工具调用及参数摘要、耗时、结果 |
| 出站 | 生成了什么、是否送出、平台回执或失败原因 |

这里的“为什么未回复”是**可观察的规则、结构化决策输出和执行元数据**；不要求也不展示模型内部隐含推理链。

## 安全控制

- 模拟模式默认不发送真实消息、不执行高风险外部写操作。
- 需要真实连通性测试时，显式切到真实测试、选定目标、显示副作用并确认。
- Prompt、工具参数和消息可能含敏感信息，须做角色权限控制、脱敏和可配置保留策略。
- 回放保留运行版本/模型版本、时间与输入快照，承认随机模型无法保证精确复现。

## 典型排障

- `Bot 没回复` → 查看触发器或主动行为决策。
- `模型不是预期的` → 查看配置继承与路由回退原因。
- `工具没用上` → 检查当前会话授权与工具是否注入。
- `模型说回复了但群里看不到` → 检查出站发送回执。

## 验收

- 能模拟一段群聊、切换人格/模型，观察实际发送给模型的上下文。
- 从真实会话和运行日志可定位相同 Trace。
- 关闭真实发送时，回放不可能触发群发言或执行写入型工具。
