# 提供商 · 模型与任务路由

**位置**：侧栏 / 提供商 · **目标**：在一个页面完成 API 连接、模型能力配置、任务模型选择和回退测试。

## 信息架构

```text
提供商                           [+ 添加提供商] [搜索]
[提供商与模型] [任务模型分配] [调用与用量（后续）]
  提供商列表：名称、协议、地址摘要、模型数、最近检测状态
  提供商详情：凭据 | 模型清单 | 测试 | 限制 | 用量
```

## 添加提供商

1. 选择接口协议：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages，后续扩展其他协议/原生端点。
2. 填入基础 URL、API Key（如需要）、备注名称；高级项包括请求头、超时、代理与请求参数。
3. 获取模型列表（端点支持时）或手动增加模型 ID；不能获取列表并不等于连接失败。
4. 单独测试文本、视觉、工具调用、流式输出等能力，形成 `支持 / 失败 / 未测` 记录。
5. 保存；模型能力允许手工覆写，但标记“用户指定、未验证”。

## 模型属性

- 模型 ID、展示名称、所属提供商、启用状态。
- 声明与实测能力：对话、视觉、工具调用、结构化输出、推理、生成图像、STT、TTS。
- 可选元信息：上下文窗口、输入/输出 Token 价格、并发上限、超时时间。
- **协议 ≠ 能力**：兼容 Chat Completions 的服务不一定支持图像输入、工具、音频；按模型与端点判断。

## 任务模型分配

| 任务槽位 | 默认策略 | 失败处理 |
|---|---|---|
| 普通聊天 | 主聊天模型 | 备用兼容模型 |
| 复杂 Agent | 推理/工具模型 | 备用工具模型 |
| 智能插话判断 | 小模型 | 回退规则或跳过 |
| 图像理解 | 视觉模型 | 降级为文本提示 |
| 图片生成 | 生图端点 | 备选生图端点或报错 |
| STT / TTS | 对应音频模型 | 明示降级为文本 |
| 记忆提取/压缩 | 低成本模型 | 排队延后，不阻断主回复 |

页面用“任务槽位卡片 + 主模型 + 按顺序回退链”呈现；可在会话页对槽位进行覆盖。

## 路由规则与回退

- 先按任务要求过滤能力不符模型，再考虑优先级、预算与当前健康度。
- 明确可回退错误类型：鉴权失败通常需要用户修正，不宜连续尝试大量端点；网络超时、限流和服务端错误可以有限重试。
- **已执行 Tool 的请求不能简单整体重放**；需要基于工具执行记录和幂等策略恢复，避免重复写文件/发送消息。
- 每次选择要记录 `requestedSlot, selectedModel, fallbackReason, providerRequestId, usage, latency, traceId`。

## 测试体验

在模型行直接“测试”：输入自定义问题；工具调用测试使用只读演示工具；语音/生图使用对应任务入口。结果包含延迟、有效响应片段、工具调用结果、Token 与错误原因。密钥原文永不放进复制诊断内容。

## 空状态与异常

- 无提供商：引导新增并显示支持协议。
- 无模型：允许手工输入模型 ID，并解释为何不能自动列出。
- API Key 错误：错误精确定位到提供商，不静默切换未告知的其他服务。
- 模型被删除但正在被路由/会话使用：显示引用数量、替代方案，删除前确认。
- 提供商暂时不可用：可保留配置并禁用；提供错误重试入口。

## 验收

- 能新增两个不同协议的提供商并测试基本对话。
- 可以为聊天任务设置主模型和备用模型，Trace 可查询路由原因。
- 任务模型或提供商下线时相关会话显示可恢复的失效状态。
- 密钥与其他敏感值在 Web、日志和导出中均受到保护。
