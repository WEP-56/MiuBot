# 交互与视觉设计原则

## 方向

目标：轻巧、安静、可理解。Miubot 名称可爱，但工作台不是玩具化后台。优先削弱视觉侵入感：少量颜色强调、清晰层级、适度留白、紧凑控制。

## 可复用组件

| 组件 | 行为要求 |
|---|---|
| 顶部工具栏 | 添加（次要突出）、搜索、过滤、更多；输入搜索时不改变内容列表锚点 |
| 状态标签 | 离线、连接中、在线、降级、异常；不可只靠颜色区分 |
| 配置来源标签 | 全局 / Bot / 当前会话 / 成员覆盖，支持恢复继承 |
| 列表项 | 标题 + 最有用状态 + 次要信息；点击进入详情；危险操作置于更多菜单 |
| 测试按钮 | 显示测试阶段、耗时和失败位置；不要只吐“连接失败” |
| 详情抽屉 | 低复杂度配置可抽屉处理；复杂连接使用单独向导 |
| 日志时间线 | 支持筛选和 Trace 跳转；隐去密钥及敏感凭据 |

## 输入与保存规则

- 常规表单 **保存后生效**；危险改动或可能中断连接的设置要求明确确认。
- 离开未保存页时给出丢失更改提示；禁止因为切 Tab 意外丢输入。
- 密钥默认掩码；允许替换而非默认回显明文；必要时提供显式“测试”操作。
- 异步操作有 loading、成功、可重试错误、取消；网络失败保留当前编辑内容。
- 插件提供的 UI 应遵守统一的标题、字段、错误、授权和保存规范。

## 反馈层级

- **内联**：字段校验、协议不支持、不可用能力说明。
- **局部**：卡片连接状态、单个模型测试结果。
- **Toast**：轻量操作结果。
- **确认弹窗**：删除人格/提供商、清空历史、发送真实测试消息、授予高危权限。
- **全局横幅**：服务不可用、数据库只读、系统升级需重启。

## 列表的默认行为

提供列表搜索、状态筛选和排序。优先保持内容锚定，避免切换搜索模式时列表大幅跳动。操作区的按钮强调程度根据使用频率设计，不应所有动作都用主色实心按钮。

## 可访问性与适配

- 键盘可遍历所有操作；表单错误与状态有文本，不只用图标表达。
- 支持浅色/深色、布局响应式、小尺寸窗口。
- 中长内容可复制；运行日志采用等宽字体；时间、Token、价格有统一格式。

## 状态文案标准

不使用含糊的“成功/失败”。例如：`WebSocket 已建立，但尚未收到心跳`、`认证通过，但发送能力未验证`、`模型可回答文本，但工具调用未通过测试`。避免制造虚假的“全部正常”感。
