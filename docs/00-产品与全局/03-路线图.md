# 路线图与优先级

> 优先级标记：P0 必须具备；P1 提升差异化；P2 后续生态。并非开发排期承诺。

## P0：最小可用闭环

**目标**：能够配置、连接、回复、定位问题。

- 运行服务与 Web 工作台；首次启动引导。
- 至少一种可用 QQ 接入方式，并为第二种方式保留适配协议接口。
- 提供商 CRUD、模型配置、文本聊天及 API 基础测试。
- 至少一个人格，绑定默认人格，支持编辑与本地调试。
- 群聊/私聊消息归档、上下文隔离、会话启停与基础触发（@、命令）。
- 消息 Trace、模型错误、发送失败能被追踪。
- 关键密钥与权限安全，基本备份与数据库持久化。

## P1：社交 Agent 体验

- 多 Bot 与任务模型路由、回退策略、用量统计。
- 会话多层配置继承与生效来源提示。
- 智能插话、注意力与冷却控制。
- 表情包导入、打标与工具检索。
- 工具、扩展和 Skills 的基本生命周期管理。
- 模拟群聊、历史回放与上下文检查。

## P2：生态与高级能力

- MCP 服务管理、图像生成、STT/TTS、长期记忆与知识库。
- 定时任务、主动发起、自动化规则、高级授权。
- 扩展 UI、第三方插件包管理、跨平台支持。
- 高级运营统计、多实例运行、可选远程同步。

## 阶段性验收

| 阶段 | 能力证明 |
|---|---|
| P0 | 接入一只 Bot、配置模型和人格、QQ 上正常收发一条消息、Web 可追踪对应 Trace |
| P1 | 指定一个群使用不同人格/模型，智能插话受冷却约束，表情包可检索并发送 |
| P2 | 插件安装后新增能力与设置页，权限可控，主动任务可以审计与撤销 |

## 必须避免的范围膨胀

- 不要求所有高级功能在前端成品之前完成；先给导航占位与状态解释。
- 不以“兼容每一个 Pi 扩展”作为核心验收；只保证声明过的兼容接口。
- 不为一次部署引入复杂集群、独立消息总线或强依赖云基础设施。
